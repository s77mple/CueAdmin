## 1. 一页结论

**Phase-1 = 把 Excel 里"每一段购销的合同/货/票/款/检测"变成可录入、可查询、双方可见、按团队隔离的记录系统。**

| 块 | 内容 | 工作量 | 性质 |
|---|---|---|---|
| A | 权限码/角色/菜单/用户/部门/岗位 | 现成 | 【现有】配置即用 |
| B | `subjects` 主体档案 + `roles.data_scope` + `core/scope.py` | 小 | 【新增·框架扩展】 |
| C | **购销（采购）记录**：交易主档（含批号）+ 合同/货/票/款子记录 + 质检记录（采购/生产两类） | 主要量 | 【新增·业务】 |
| D | 团队/主体/权限码/角色/用户 seed | 小 | 配置 |

**本期明确不做**：OSS 附件上传（合同/票只录字段）、自动对账/勾稽引擎、**销售台账（我方作为卖方的独立销售记录；卖方段经对方采购记录只读可见）**、**任务流/待办派单/流程引擎（纯记录制）**、外部供应商自助登录、历史数据回填。

## 2. 需求（已与用户确认）

### 2.1 核心诉求
> "某一个流程的货票款，在**双方账号上都能看见**——既是自己上游发货的看得见，自己也看得见。"（用户原话）

收敛成两条规则：
- **读**：一条交易记录里，只要 **采购方 或 供应商 任一主体在我的数据范围内**（或我 `all`），我就能看到这条记录及其合同/货/票/款/检测——两个有账号的团队彼此可见对方那一端。
- **写**：记录**买方 = 昌农/GH/GP 及其代管抬头（立博、客都文旅等）** 的采购段；录单人 = 买方所属/代管团队（自录或代录，照 Excel 权限）。**销售侧不建销售台账**——卖方段的货票款以"对方采购记录"形式呈现、卖方团队只读可见（如 立博←GP 柚苷：买方立博由昌农代录，GP 团队作为供应商可见该笔、只读）。

### 2.2 权限分工（Excel Sheet1 原话）
| 人 | 录入范围 |
|---|---|
| 昌农商贸人员 陈雄珍/谭明平 | 昌农商贸向其**上游供应商**采购农产品的 合同/货(数量单价规格含量)/款/票/含量检测 |
| 金骏康/金柚康采购人员 鲍雅丹/罗文燕 | GH/GP 向其**上游供应商**采购/代工产品的 合同/货/款/票/含量检测 |
| 金柚康质检人员 林丽薇 | GH/GP 采购/代工产品**经金柚康检测**后的 规格/水分/含量 |

### 2.3 两种流程模板（决定录入哪些字段）
1. **贸易类**：供应商A → 我方 → 客户（金柚康）
2. **代工类**：GH/GP 提年度需求 → 我方（昌农）付预付款 → 供应商发货（磅单1发货前/磅单2代工厂收货前）→ 代工厂检测 →（含量达标√；不达标重新议价）→ 同步签两份合同（我方与供应商、我方与 GH/GP）。**合同数量以代工厂收货磅单为准。**

> **记录一律是采购视角**，且不因买方是否登录而省略：买方可以是昌农/GH/GP 自己（其团队自录），也可以是**其代管抬头 立博/客都文旅**（由代管团队录，如 立博←GP 柚苷 由昌农团队录）。凡"我方体系为卖方"的段不建销售台账，但以对方采购记录呈现、我方团队只读可见。供应商主体照实际发票抬头选。Excel 两套模板本身即采购模板。

## 3. 决策记录（已锁定）

| # | 决策 | 来源 |
|---|---|---|
| D1 | 每笔交易 = **一条共享记录**（主档+子记录），不搞"双方各自录自己侧再勾稽" | 用户原话（双方可见）+ 选型 |
| D2 | 系统录**买方 = 昌农/GH/GP 及其代管抬头（立博/客都文旅）** 的采购段，录入 = 买方所属/代管团队；卖方不建销售台账，但以对方采购记录被卖方团队只读可见 | 用户多次确认（采购方单方录/双方可见/销售端不建账/立博采购GP 由昌农代录） |
| D3 | 记录粒度 = **主档 + 可多条票/款**（票后补、分次付款、账期可挂多条） | 用户选定 |
| D4 | **不做独立批次/对账容器**：批号由采购人录入采购时填写、随记录生成，作为串联与筛选维度；保留 **data_scope 团队隔离** | 用户"批号由昌农采购填写、录入时生成" |
| D5 | 字段**照 Excel**，一期先"录字段"，**OSS 附件不上传** | 用户明确 |
| D6 | **自动对账/勾稽引擎不做**；"双方可见 + 单条共享"本身不需要对账 | 用户明确 |
| D7 | 质检金额不涉及（含量/水分/规格），检测记录与金额记录分离 | 沿用原稿 |
| D8 | 外部主体（果农/立博/客都文旅）不登录，由代管团队代录 | Excel 权限分工 |
| D9 | **检验两分类通用**：检测记录分「采购检验(收料/到货) / 生产检验(产出/出库)」两类；质检独立于购销记录、可挂批号——覆盖 GP 自产柚苷(段④) 等无票产出段的检验 | 用户选定 |
| D10 | **纯记录制**：不做任务流 / 待办派单 / 催办 / 状态机；谁发生谁录、票可后补、顺序自由 | 用户选定 |

> 取代早稿的部分：原"按单据类型拆 9 个模块 + 跨团队批次对账 + 我方销售侧记录"范围**收窄**为"统一采购记录 + 双方可见 + 批号维度 + 团队隔离"；原 D4 全链只读与"单条共享可见"语义以本条为准。

| **2.3.2 金柚康检测结果** | 待检测产品名称、检测(到样)日期、含量%、打粉后水分、复测日期、复测含量%、备注 |

## 5. 数据模型规格（草案，供评审）

> 数量一律数值；金额一律 `Numeric(18,2)`。金额只出现在 合同/票/款 子表；**质检表无金额字段**。

```
subjects          主体档案（code/name/kind/owner_department_id/…，同前版）
deals             交易主档（一笔=一购销段；带 batch_no 批号）
deal_contracts    合同（0..1 per deal）
deal_deliveries   收货/货（0..1 per deal）
deal_invoices     票（0..n per deal）
deal_payments     款（0..n per deal）
quality_tests     质检（独立于购销；无金额；见下两行）
```

**deals 主档关键列**：`id`、`deal_no`、`template_type`(trade/manufacture)、`batch_no`(**批号 = 该批来源货的身份号**，原料采购录入人填写/生成；**同一批货从原料经各手流转、代工/自产产出全程沿用同一批号**，下游采购与质检记录照填此号，不按产品阶段另起号——不同来源的货才另起批号)、`buyer_subject_id`(采购方=我司抬头)、`seller_subject_id`(供应商)、`status`(草稿/进行中/已完结)、`recorded_by`、时间戳。
**子表挂** `deal_id`，字段按 §4 对应块。

- 票/款可为多条：一条票只存 `发票金额`，`未付款金额` 由 合同金额 − Σ已付 现算（不再手工填，减少出错）——§12 O2 待确认。
- **质检独立建模** `quality_tests`：一条 = 一次检测。关键列 `inspection_stage`(采购检验=收料/到货；生产检验=产出/出库)、`subject_id`(被检抬头)、`product`(待检产品名，如 柚苷/新橙皮苷)、`detector`(代工厂/金柚康/双方确认)、`batch_no`(批号)/`deal_id`(关联采购记录，可空)。字段照 §4.2 2.3（含量/整果测水分/打粉后水分/复测…），**无任何金额**，可复测多次。
- `deal_id` 可空 = 专门覆盖**自产柚苷(段④)这类无购销段的产出检验**——不挂在任何买卖上，挂批号即可。
- **到货质检原则**：凡采购到货都有采购检验、凡产出都有生产检验——GP 收干柚果、收新橙皮苷各自到货检验；GP 自产柚苷、立博产新橙皮苷各自生产检验（质检记录无金额）。
- 我方校验：创建时 采购方(buyer) 主体 ∈ 我的范围（团队隔离）；可见性见 §6.3。

**Phase-1 检验点落位（示例，界面不漏检测；质检靠批号筛选，不依赖某销售段）**
| 检验 | 环节 | 被检抬头 | 产品 | 关联 | 检测方 |
|---|---|---|---|---|---|
| 干柚果到货检验 | 采购检验 | GP | 干柚果/片 | 批号 | 金柚康 |
| 立博收柚苷 | 采购检验 | 立博 | 柚苷(收料) | 批号 | 代工厂/金柚康 |
| 立博产新橙皮苷 | 生产检验 | 立博 | 新橙皮苷(产出) | 批号(关联昌农采购记录) | 代工厂/金柚康复测 |
| GP 自产柚苷产出 | 生产检验 | GP | 柚苷(自产产出) | 批号（段④无票） | 金柚康 |
| GP 新橙皮苷到货 | 采购检验 | GP | 新橙皮苷(到货) | 批号(关联 GP←昌农 采购) | 金柚康 |

## 6. 权限与可见性

### 6.1 框架扩展（同前版，微调）
- `roles` 加列 `data_scope`（`team`/`all`）+ schema/表单/Alembic 迁移。
- 新增 `subjects` CRUD（仅 admin）。
- 登录响应 / `/auth/me` 追加 `my_subjects`、`scope_all`。

### 6.2 行级闸（`core/scope.py`）
`resolve_subject_ids(user)` → None(全) 或 set；写前 `ensure_subject_allowed(user, subject_id)`。创建 `deals`（采购方主体）及 票/款 都落在范围主体上。

### 6.3 交易可见性（D1/D2 核心）
- **读 deal**：`user` 可见条件 = `data_scope='all'` **或**（`buyer_subject_id ∈ 我的范围` **或** `seller_subject_id ∈ 我的范围`）。
- **写 deal 及子记录**：录"买方属于我方体系"的采购（含代管抬头如 立博，由代管团队录）；`buyer_subject_id ∈ 我的范围` 才可建/改/删（对方只读）。卖方侧不建独立销售台账。
- 后端实现：deal 列表 SQL 加 `(buyer_id IN scope OR seller_id IN scope)`；写前校验主体范围。
- 质检记录：独立质检模块，**采购/生产两类都录**；读走 QC 角色（`all` + 无金额）；QC **不授交易/票/款菜单**（D7）。

### 6.4 错误码
范围外读写统一 `BusinessException(ErrorCode.ACCESS_DENIED, "该交易/抬头不在你的数据范围内")`，HTTP 200 + code 按框架规范。

## 11. 验收标准（Phase-1）
1. 陈雄珍录"昌农←果农 干柚果/片 采购"：能录合同/收货/票/款字段，采购方=昌农在范围内；**录入时填写批号**，保存后随记录生成。
2. **双方可见**：GP 作为采购方的段都录——鲍雅丹录"GP←昌农体系 干柚果/片 原料 采购"与"GP←昌农 新橙皮苷 采购"，昌农（供应商侧）团队可见、只读不能改；反之亦然。
3. **代录代管买方**：立博←GP 柚苷 采购由昌农团队代录（买方=立博、供应商=GP），GP 团队作为供应商只读可见；系统不单独建 GP 的销售台账。
4. 林丽薇能录**采购检验**与**生产检验**两类质检记录（无金额列，看不到交易金额）；GP 收干柚果、收新橙皮苷的到货检验与 立博产出、GP 自产柚苷的生产检验都在。
5. 票后补/分次付款：同一条记录加第二条票、第二条款成功，未付款自动算。
6. data_scope：昌农人建不了"采购方=GP"的记录；`all` 档（陈总）全可见。
