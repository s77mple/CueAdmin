# CueAdmin 部署手册

前端静态文件放 OSS，后端跑服务器，两个独立域名。

```
前端   cue-admin.<root>  →  DNS CNAME  →  ESA  →  cue-adm.oss-cn-shenzhen.aliyuncs.com
后端   cue-api.<root>    →  DNS A      →  服务器 nginx:443  →  127.0.0.1:8000 (gunicorn)
```

**两条链路独立。** 后端不走 ESA；ESA 上不需要任何 `/api` 转发规则。
**OSS 侧不绑域名**，ESA 回源直接用 Bucket 默认域名。

---

## 前置准备

| 项 | 要求 |
|---|---|
| 域名 | 已备案的根域名（备案按根域名办，子域名不用重复备案） |
| 服务器 | 2C4G 起，装好 MySQL 8.0+ / Redis 6.0+ / Python 3.12+ |
| OSS | 一个 Bucket，地域 `cn-shenzhen` |
| ESA | 一个站点，绑定根域名 |

子域名规划：

```
cue-admin.<root>    前端（CNAME → ESA）
cue-api.<root>      后端（A → 服务器 IP）
```

## 一、后端上线

### 1.1 拉代码、装依赖

```bash
cd /www/wwwroot
git clone <仓库地址> cueadmin
cd cueadmin/backend

python3.12 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

> Python 必须 >= 3.12。
> 若用宝塔「Python 项目管理器」建 venv，路径是 `/www/server/pyporject_evn/cueadmin/`，
> 下面命令里的 venv 路径要跟着换。

### 1.2 配置环境变量

```bash
cp .env.example .env
vim .env
```

| 变量 | 填什么 |
|---|---|
| `DATABASE_URL` | `mysql+aiomysql://用户:密码@127.0.0.1:3306/cueadmin` |
| `JWT_SECRET` | 随机串，生成命令见下 |
| `JWT_ALGORITHM` | `HS256` |
| `JWT_ACCESS_EXPIRE_MINUTES` | `15` |
| `JWT_REFRESH_EXPIRE_DAYS` | `7` |
| `REDIS_URL` | `redis://127.0.0.1:6379/0` |
| `APP_ENV` | `production` |
| `DEBUG` | `false` |

```bash
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

> ⚠️ `DATABASE_URL` / `JWT_SECRET` 不填或填默认值，**应用会拒绝启动**（`validate_secrets()` 硬校验）。
> `JWT_SECRET` 泄露 = 任何人可伪造 token。**不要提交进 git。**

### 1.3 建库 + 建表 + 种子数据

```bash
mysql -u root -p -e "CREATE DATABASE cueadmin CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci"
python seed.py
```

输出末尾会打印 `默认账号: admin / admin123`。

> ⚠️ 首次登录后立刻改密码。

### 1.4 装 gunicorn、起进程守护

```bash
# gunicorn 不在 requirements.txt 里，单独装
/www/wwwroot/cueadmin/backend/venv/bin/pip install gunicorn
```

宝塔「进程守护管理器 → 添加进程」：

| 项 | 值 |
|---|---|
| 名称 | `cueadmin` |
| 启动命令 | `/www/wwwroot/cueadmin/backend/venv/bin/gunicorn app.main:app -b 127.0.0.1:8000 -w 2 -k uvicorn.workers.UvicornWorker` |
| 运行目录 | `/www/wwwroot/cueadmin/backend` |
| 启动用户 | `root` |

> ⚠️ **运行目录必须填 `backend/`。** `app/core/logger.py` 里 `logs/app.log` 是相对路径，
> 相对的就是这个目录，填错日志会跑到别处。
>
> ⚠️ **不要加 `--reload`**（开发用的热重载，线上会拖慢并导致进程异常）。

`-w 2` 是推荐值。引擎配置 `pool_size=10, max_overflow=20`，单 worker 最多占 30 条连接，
**`-w 2` = 最多 60 条**。同一台服务器还有别的服务，一起算，别超 MySQL 的 `max_connections`。

### 1.5 反向代理 + SSL

宝塔「网站」页面有独立的**「反向代理」**入口，**不需要先「添加站点」**：

| 项 | 填什么 |
|---|---|
| 代理域名 | `cue-api.<root>` |
| 目标 URL | `http://127.0.0.1:8000` |

生成的配置里有 `location ^~ / { proxy_pass http://127.0.0.1:8000; }` —— 全路径转发，
因为这个域名只服务后端。

> 配置里会有一行 `root /www/wwwroot/cue-api.<root>;`，那是宝塔模板固定带的，
> 目录不会被用到（所有请求都转给后端了），无视即可。

**然后申请 SSL 证书**（对应域名的 SSL 设置 → Let's Encrypt 一键申请）。

### 1.6 验证

```bash
# 本机
curl http://127.0.0.1:8000/health

# 走域名（DNS 还没配时用 --resolve 临时指定）
curl --resolve cue-api.<root>:443:<服务器IP> https://cue-api.<root>/health
```

期望 `{"status":"ok","database":"ok","redis":"ok"}`。**任何一个不是 `ok`，先别往下走。**

## 二、DNS 解析

阿里云「云解析 DNS」加两条：

| 主机记录 | 类型 | 记录值 | 说明 |
|---|---|---|---|
| `cue-api` | **A** | 服务器公网 IP | 先加，因为申请 SSL 要验证 |
| `cue-admin` | **CNAME** | ESA 给的接入地址 | 做完第三步拿到值再加 |

## 三、前端构建 + 上 OSS

### 3.1 填后端地址

`frontend/.env.production`：

```bash
VITE_API_BASE_URL = https://cue-api.<root>
```

> ⚠️ 这个值**写死进构建产物**，换后端要重新构建。
> **必须是 `https://`** —— 前端 HTTPS 请求 HTTP 接口会被浏览器以 Mixed Content 拦掉。

### 3.2 构建

```bash
cd frontend
pnpm install
pnpm build
```

产物在 `frontend/dist/`。

### 3.3 建 Bucket + 上传

「OSS 控制台 → Bucket 列表 → 创建 Bucket」：

| 项 | 值 |
|---|---|
| 名称 | `cue-adm`（参考现有：`sales-adm` / `develop-adm`） |
| 地域 | `cn-shenzhen` |
| 读写权限 | **照抄现有前端 bucket 的值**（见下） |

然后「文件管理 → 上传」，把 `dist/` 里的**内容**（不是 dist 目录本身）传到 **Bucket 根目录**：

```
index.html
assets/index-xxxxx.js
版本文件
```

> ⚠️ **读写权限必须是「公共读」**（照抄现有 bucket）。
> ESA 回源用的是 OSS 默认域名，**私有读会返回 403**。

### 3.4 OSS 侧不用配别的

不绑自定义域名、不传 SSL 证书 —— 域名 / HTTPS / 缓存全在 ESA。
OSS 控制台的「域名管理」是空的，正常。

## 四、ESA 配置

### 4.1 添加域名（必须）

「ESA 控制台 → 站点 → 域名 → 添加域名」：

| 项 | 值 |
|---|---|
| 主机名 | `cue-admin.<root>` |
| 源站类型 | **OSS** |
| 源站 | Bucket 的**外网访问域名**，从「OSS → 概览 → 外网访问」复制 |
| 加速类型 | **网站页面** |

> ⚠️ 别复制成**内网**那个（带 `-internal`），只能在阿里云内网访问。

ESA 会给一个 CNAME 地址（形如 `cue-admin.<root>.a1.initba.com`），**填回第二步的 DNS**。

配完对着检查：

| 列 | 期望 |
|---|---|
| HTTPS 证书 | 已配置（ESA 自动签发续期） |
| CNAME 状态 | **已配置**（显示「待配置」= DNS 没加或没生效） |

### 4.2 缓存规则（可选）

**不配也能跑**，ESA 有默认策略。配它只为消除一个不确定性：

| 文件 | 要不要管 |
|---|---|
| `assets/index-BzXuAejY.js` | ❌ **不用管** —— 名字带 hash，内容一变文件名就变 |
| `index.html` | ⚠️ **要管** —— 名字永远不变，被缓存住前端更新后用户看到的还是旧页面 |

**先不配，上线后测一次：**

```bash
# 看有没有被缓存（Age > 0 = 被缓存了）
curl -I https://cue-admin.<root>/index.html

# 改一行前端 → 重新构建 → 传 OSS → 再访问
# 是新版本 = 默认策略没问题；还是旧的 = 配一条 index.html 不缓存
```

### 4.3 内容压缩（可选）

```bash
curl -I -H "Accept-Encoding: gzip" https://cue-admin.<root>/assets/index-xxx.js
# 有 Content-Encoding: gzip = 已经压了，不用配
```

> **不要给 `cue-api.<root>` 在 ESA 上配任何东西** —— 它不走 ESA（DNS 是 A 记录直连）。

## 五、验收清单

| # | 检查 | 期望 |
|---|---|---|
| 1 | `ps aux \| grep gunicorn` | 1 主 + 2 子 |
| 2 | `curl 127.0.0.1:8000/health` | `{"status":"ok",...}` |
| 3 | 浏览器开 `https://cue-api.<root>/health` | 同上，证书有效 |
| 4 | `https://cue-api.<root>/docs` | 能看到 Swagger |
| 5 | `nslookup cue-admin.<root>` | 解析到 ESA |
| 6 | `nslookup cue-api.<root>` | 解析到服务器 IP |
| 7 | 打开 `https://cue-admin.<root>` | 看到登录页 |
| 8 | **登录** `admin` / 改过的密码 | 能进后台，侧边栏有菜单 |
| 9 | F12 → Network → 看登录请求 | 200，**无 CORS 报错** |

**第 8 步是分水岭** —— 能登录 = 前端找到后端了 + CORS 通了 + 后端连上 MySQL 和 Redis 了。

## 六、常见问题

### 登录报 CORS 错误

**先看 Network 里那条请求的真实状态码。**

返回 500/502 的话，CORS 报错是假象 —— 真实问题是后端挂了或反代配错，响应里本来就没 CORS 头。

后端正常时，检查 `app/main.py` 的 `CORSMiddleware`。当前 `allow_origins=["*"]` + `allow_credentials=False` 是合法且够用的。

> ⚠️ `allow_origins=["*"]` 和 `allow_credentials=True` **不能同时用**（浏览器规范禁止）。

### Mixed Content

`.env.production` 里写成了 `http://`。改成 `https://` 重新构建。

### 接口 404

请求打到前端域名上了。检查：

```bash
grep -r "cue-api" dist/          # 构建产物里有没有写进去
```

改 `.env` 后**必须重新 `pnpm build`**。

### 前端更新后还是旧页面

`index.html` 被缓存了。去 **ESA 缓存规则**里改成不缓存（缓存是 ESA 管，OSS 不用动）。

### 后端启动就退出

`validate_secrets()` 拦住了。看 `/www/server/panel/plugin/supervisor/log/cueadmin.err.log`。
检查 `.env` 位置（要在 `backend/` 下）和内容。

### 改了表结构

```bash
cd backend
alembic check                                     # 先看有没有漏做的迁移
alembic revision --autogenerate -m "描述改动"
alembic upgrade head
```

> 不要重新跑 `python seed.py`（只管首次建表）。
> **绝不手写 `op.alter_column` 改列定义**（历史事故：丢过全库主键的 `AUTO_INCREMENT`）。

### 强制 HTTPS

宝塔 SSL 页面默认只「部署证书」不「强制跳转」，即 `http://` 仍能访问。
**接口建议打开强制 HTTPS** —— 否则手动输域名时那一次是明文。

## 七、日常运维

### 日志

| 日志 | 路径 | 什么时候看 |
|---|---|---|
| 应用 | `/www/wwwroot/cueadmin/backend/logs/app.log` | 业务报错 |
| 进程 | `/www/server/panel/plugin/supervisor/log/cueadmin.err.log` | **后端起不来** |
| nginx | `/www/wwwlogs/cue-api.<root>.log` | 请求到没到 |

排查顺序：**进程日志（起没起来）→ 应用日志（报什么错）→ nginx（请求到没到）**。

### 常用

```bash
# 重启后端（改完代码 / 改完 .env）
# 宝塔「进程守护管理器 → 重启」

mysqldump -u root -p cueadmin > cueadmin_$(date +%F).sql
ps aux | grep gunicorn
```

### 更新代码

```bash
cd /www/wwwroot/cueadmin && git pull

cd backend && source venv/bin/activate
pip install -r requirements.txt    # 依赖有变动时
alembic upgrade head               # 表结构有变更时

# 回宝塔重启 cueadmin
```

前端更新：

```bash
cd frontend && pnpm build
# dist/ 重新传到 OSS（先清空旧文件，避免残留）
```

### 证书

**后端域名**：宝塔自动续（计划任务里的 `acme_v2.py --renew_v2=1`）。随时可查：

```bash
echo | openssl s_client -connect cue-api.<root>:443 2>/dev/null | openssl x509 -noout -dates
```

到期日往后推 = 续期正常。**前端域名不用管**，ESA 全自动。
